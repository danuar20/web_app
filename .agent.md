# NetKPI Monitor — Agent System

This repository uses specialized agents (files in `agents/`) to divide responsibility for backend, UI, testing, performance, security, and architecture tasks.

## Agents (location)

All agent definitions live in `agents/`:

- `agents/architect-agent.md` — planning, coordination, DoD checks
- `agents/backend-agent.md`    — Flask routes, SQL, data pipelines
- `agents/ui-agent.md`         — templates, Chart.js, CSS/UX
- `agents/tdd-agent.md`        — tests, coverage, regression checks
- `agents/perf-agent.md`       — caching, query tuning, scalability
- `agents/security-agent.md`   — auth, input validation, secrets

## Quick Start (what an agent should do)

1. Read `shared-rules.md`, `forbidden-actions.md`, then `definition-of-done.md`.
2. Open the relevant `agents/<agent>-agent.md` for task-specific constraints.
3. Make minimal, well-tested edits in the workspace under `web_app/`.
4. Run or add tests in `web_app/tests/` and report results.

## Current file ownership (concise)

- Backend: `app/` (blueprints in `app/routes/`, `app/__init__.py`, `app/db/`)
- UI: `templates/`, `static/` (Chart.js code and CSS)
- Tests: `tests/` (or `web_app/tests/`)
- Agents & governance: `agents/`, `shared-rules.md`, `definition-of-done.md`, `forbidden-actions.md`

## Notes about this workspace

- The Flask app uses an app factory in `app/__init__.py` and registers blueprints from `app/routes/`.
- DB helpers are under `app/db/` (e.g. `db_webapp.py`, `db_pumaz.py`). Use environment variables for credentials.
- Templates live at `templates/` and are rendered with Jinja context (data keys like `chart_labels`, `payload_after`, etc.).

## How to ask for changes

- Bug fixes: mention route or template (e.g. "fix /login 500" or "productivity chart missing year-after line").
- New features: include desired route, inputs, and expected template keys.
- Tests: ask TDD agent to add tests under `web_app/tests/` referencing `pytest`.
